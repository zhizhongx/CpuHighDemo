# CPU 线上事故模拟设计

## 目的

把现有的显式高 CPU 示例升级为一个本地“线上事故”练习。学习者在 AI 辅助下主动收集证据，最终定位稳定占用 CPU 的线程、调用栈和代码位置，并说明临时止损与修复思路。

## 目标

- 提供一个独立入口，启动多个具有业务化名称和不同状态的线程。
- 仅有一个线程持续消耗约一个 CPU 核心，根因在练习前不公开。
- 练习可以通过 IDEA 启动和停止，不依赖数据库、网络或 Docker。
- 诊断通过标准：两次 CPU 采样锁定同一线程，三份线程转储得到稳定调用栈，并形成根因证据链。
- AI 只根据学习者主动提供的证据辅助分析；卡住时使用分级提示，不一次给出完整命令链。

## 非目标

- 不模拟整机所有 CPU 核心 100%。
- 不制造内存泄漏、数据库写入或不可恢复的数据变更。
- 不替代真实生产环境中的监控、告警和变更审批。

## 约束与安全

- Java 21，Windows PowerShell，继续使用当前 Maven 项目。
- 默认只占用一个逻辑核心，可在 IDEA 中直接停止。
- 场景源码放在独立包中；练习开始前提示学习者不要打开该包。
- 必须提供可停止的内部生命周期，以便自动化测试不会遗留高 CPU 进程。

## 考虑过的方案

1. **显式单线程死循环**：实现最简单，但已证明只会训练照抄命令，舍弃。
2. **本地隐藏故障、多线程模拟**：安全、可重复且能训练证据链，采用。
3. **直接在真实业务项目制造故障**：真实性最高，但业务干扰和误操作风险较大，留到后续阶段。

## 练习完成标准

学习者能够在 AI 辅助下说明并完成：确认异常 Java 进程、连续采样线程 CPU、匹配线程 ID、对比多份线程转储、定位代码、解释原因，以及提出安全的止损和修复方向。
